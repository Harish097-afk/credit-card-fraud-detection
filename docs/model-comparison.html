Explore the reported model-comparison experiment, prediction time, and the relationship between review capacity, recall, and precision. Hover over chart points for exact values.

Reproducibility: these values were supplied from project notebook experiments; this page does not run model training. Results may depend on data split, random seed, package versions, and hardware. They should not be interpreted as a direct head-to-head against published results from a different protocol.

How the project extends the research workflow

TechniqueWhy it mattersProject status
Stratified train/validation/test splitPreserves rare fraud examples while keeping threshold selection separate from final test evaluation.Implemented in training pipeline.
SMOTE on training partition onlyAddresses class imbalance while avoiding synthetic records in validation/test sets.Implemented.
Soft-voting ensemble: RF + LightGBM + XGBoostCombines probability estimates from different tree-based learners.Implemented and compared with base models.
Validation-selected thresholdSeparates score ranking from the class decision rule and avoids test-set threshold tuning.Implemented; F1 is the current selection objective.
Top-risk capacity reviewRanks transactions to match a review team's limited investigation capacity.Implemented in batch UI; ranking is not a confirmed fraud label.
Calibration and cost-sensitive thresholdsCould improve probability reliability and align decisions with false-positive/false-negative costs.Recommended future experiments; not yet claimed as implemented.
Chronological holdout and drift monitoringTests performance on later transactions and changing fraud patterns.Recommended before any deployment claim.
Paper-inspired model comparisonCompare SVM, KNN, RF, bagging, AdaBoost and voting under the same split, metrics, and evaluation policy.Research direction; not a reproduction of the paper.
